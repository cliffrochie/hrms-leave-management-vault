07A · Leave Form – Common Data Inventory

Spec card (not a screen) · Source: gathered-data §1.1.1 leave-type table + §4 CS Form 6 mapping
How the common base was derived
Every one of the 15 leave types in §1.1.1 is described with the same six attributes: Leave Type · Legal Basis · Allocation/Entitlement · Filing Window · Required Attachments · Accrual/Deductibility. All of them are filed on CS Form 6 (Items 1–7). A field that every type needs, whatever its rules, belongs in the base form. Anything that only some types need goes into a type-specific slot.

Conclusion

  1. 12 common fields make up the base form. Five are auto-filled, one is a default, and only four need typing: type, details, dates, and attachments. The signature is the fifth input.
  2. The six columns of the §1.1.1 table act as the per-type rule profile. The form reads the profile; it doesn't hard-code rules for each type.
  3. The day unit varies (working, calendar, months, days with no dates). The base form keeps one "No. of days" field and shows the unit beside it.
  4. Everything in table C goes into one dynamic slot (07B, section D). Adding a new leave type means adding a profile and slot fields, without redesigning the form.
  5. These attributes are the schema for the Leave Type Builder (25). CHRMO can add a future type, such as a Wellness Leave, by filling them in, with no code change.

Annotations

  1. Items 1–5 are always auto-filled from the HR masterfile. Track and branch are hidden on the printout but decide eligibility and routing.
  2. Choosing the type loads the rule profile (the six §1.1.1 columns), and every section below reacts to it.
